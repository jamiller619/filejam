Run tasks 01 through 30 in order. One task per chat; never concurrently.
This file is the single prompt document. The status document created by task 01

files named by its task even if a previous agent described them.

The architecture is prescribed below. Implementers choose ordinary local variable

it compiles. All its numbered checks must pass or be explicitly BLOCKED.

not justify skipping review or claiming that tests prove everything.

DESIGN -- THESE DECISIONS ARE CLOSED

D1. Product boundary

Keep Electron and the existing repository. Add one Rust executable that reads
immediate directory contents. No database, scanner, index, watcher, recursive
listing, favorites, collections, saved preferences, thumbnails, native icons,
file sizes/timestamps, opening files, mutations, production packaging, or macOS
certification. Turso is a later decision; do not add it here.

Windows is the validation target. Use release Rust builds for performance.
Show hidden entries. No natural/locale sort. No persistence for proof options.

Finish enumeration, filtering, and global sorting BEFORE any row is visible.
Deliver the prepared view in ordered batches. Existing visible rows never
reorder when a later batch arrives. Enumerating a changing filesystem is not an
atomic snapshot; do not claim otherwise.

D3. Wire schema and errors

UTF-8 JSON Lines, one object per newline. Accept LF and CRLF. No blank lines.
Every message has v:1 and type. Reject unknown fields in both implementations.
No null substitutes for required strings/arrays/numbers.

Commands:
  {v:1,type:"list",id,path,options:{nameContains,kind,sortDirection}}
  {v:1,type:"next",id}
  {v:1,type:"cancel",id}
  {v:1,type:"shutdown"}

Responses:
  {v:1,type:"ready"}
  {v:1,type:"listing",id,path,parentPath,total,
    metrics:{enumerationMs,filterSortMs}}
  {v:1,type:"batch",id,offset,entries:[{path,name,kind}]}
  {v:1,type:"done",id,total}
  {v:1,type:"cancelled",id}
  {v:1,type:"error",id,code,message}

Types/limits:
  id: ASCII matching ^[A-Za-z0-9-]{1,64}$
  path: string, nonempty, no NUL, at most 32768 UTF-8 bytes
  parentPath: same path type or null
  name: nonempty Unicode string; no NUL
  nameContains: string, at most 1024 Unicode scalar values, no NUL
  options.kind: "all" | "file" | "directory"
  entry.kind: "file" | "directory" | "symlink" | "other"
  sortDirection: "asc" | "desc"
  total/offset: integer 0..250000
  durations: finite nonnegative number in milliseconds
  code: INVALID_REQUEST | NOT_FOUND | NOT_DIRECTORY | PERMISSION_DENIED |
        UNSUPPORTED_PATH | IO_ERROR | LIMIT_EXCEEDED
  message: string of at most 4096 UTF-8 bytes (truncate diagnostics safely)
  whole line limit: 1048576 bytes excluding newline
  batch limit: 256 entries AND 524288 encoded bytes including object, not newline
  enumeration cap: 250000 immediate entries BEFORE filtering

Main adds SERVICE_UNAVAILABLE to the renderer-facing error union only.
No ORM/database/library/volume IDs or synthetic dates/sizes in these types.

Parse errors, bad version/type/id, missing fields, unknown fields, wrong JSON
types, oversized lines and invalid UTF-8 are fatal protocol errors: stderr and
exit nonzero. A structurally valid list with invalid path/options VALUES emits
INVALID_REQUEST for its id without starting work. Bad kind/direction enum values
are list-argument errors, not a crash. Deserialize these two fields as strings,
then validate them into internal enums. The main client validates its own calls
before sending; Rust still validates them independently.

Protocol termination cancels all unfinished work by connection loss; the
exactly-one-terminal rule applies while the connection remains usable.
Duplicates of an active id are fatal, not a second error event with that id.
Main generates new monotonic IDs "r-1", "r-2", etc.; never reuse within a session.

No automatic retry/restart. Missing/unresponsive/crashed service is visible.

D4. Paths, identity, and listing

Accept fully qualified drive paths and UNC share paths on Windows. Reject
relative paths, C:relative, root-relative paths such as backslash-temp, Win32
device namespace paths, NULs and parent-traversal components ("..").
"." components may be removed. Do not use URL parsers for filesystem strings.

Check the requested path's existing components with symlink_metadata BEFORE
canonicalization. Reject any reparse point/symlink component as UNSUPPORTED_PATH.
On Windows use std::os::windows::fs::MetadataExt::file_attributes and the named
constant FILE_ATTRIBUTE_REPARSE_POINT = 0x400. This includes junctions.
Only after these checks canonicalize, then confirm directory type.
Return the canonical absolute path, including a Windows extended prefix if Rust
returns one. Subsequent requests must accept the extended drive/UNC form produced
by canonicalize, but never device forms such as \\.\ .
Use Path::parent for parentPath; drive and UNC share roots have null parent.
Test these cases explicitly. Component checks are best-effort, not a sandbox
against filesystem replacement races.

Enumerate with std::fs::read_dir. Call DirEntry::file_type for classification.
On Windows, if reparse-point detection requires symlink_metadata per entry, do
that and record this enumeration cost; do not claim zero metadata calls.
Never follow entries. Reparse/symlink entries are kind "symlink" and non-navigable.
Do not request size/date fields. Any enumeration/classification error fails the
entire listing; do not emit partial success.

No to_string_lossy for actionable paths. A non-Unicode name/path produces
UNSUPPORTED_PATH rather than a potentially wrong navigable path.
Temporary view identity is the full path. It is not durable across moves.

Map std::io::ErrorKind NotFound to NOT_FOUND, PermissionDenied to PERMISSION_DENIED,
NotADirectory to NOT_DIRECTORY, all other I/O to IO_ERROR. Invalid arguments,
link rejection, Unicode rejection, and entry limit use their explicit codes.

D5. Pure filtering and sorting

Compute lowercase(name) once per entry and lowercase(nameContains) once.
Do not trim the filter; no glob/regex behavior.
Filter by literal lowercase substring and exact requested kind (unless all).
Then sort by:
  group: directory=0, everything else=1 (ALWAYS ascending)
  within group: tuple(lowercase_name, original_name, full_path)
For desc, reverse only the tuple comparison, not group order.
Use Rust string ordering. Release temporary lowercase keys after preparing view.
Full path is the tie-breaker. Never sort independently in JS.

Fixed real-filesystem fixture:
  directories: Alpha, zeta
  files: .hidden, Beta.txt, file10.txt, file2.txt, résumé.txt, space name.txt
  nested file: Alpha/inside.txt (must NEVER appear in root listing)

Expected ascending all names:
  Alpha, zeta, .hidden, Beta.txt, file10.txt, file2.txt, résumé.txt, space name.txt
Expected descending all:
  zeta, Alpha, space name.txt, résumé.txt, file2.txt, file10.txt, Beta.txt, .hidden
Filter nameContains="FILE", all, asc:
  file10.txt, file2.txt
Filter kind=directory, desc:
  zeta, Alpha
Filter nameContains=" ", all:
  space name.txt
Filter nameContains="absent":
  []
Use additional pure in-memory entries "a", "A" on distinct paths for case ties;
do not try to create case-only sibling files on a case-insensitive Windows volume.

D6. Prescribed service concurrency -- do not invent another model

Exactly three threads:
  main thread = controller + ONLY stdout writer
  reader thread = bounded stdin framing + command parsing
  worker thread = filesystem preparation (including filtering/sorting)

Reader and worker send into ONE std::sync::mpsc::sync_channel<Event>(32).
Event is Command, Prepared{id,result}, InputClosed, or FatalInput.
Main blocks on recv; no polling/timeouts in its normal loop.
Main emits serialized JSON with write_all + newline + flush. No other thread
writes stdout. stderr diagnostics may originate elsewhere.

Worker mailbox:
  Arc<(Mutex<Mailbox>, Condvar)>
  Mailbox { pending: Option<Job>, stopping: bool }
  Job { id, path, validated_options, cancelled: Arc<AtomicBool> }
submit(job) replaces the pending slot and notifies the condvar.
The controller marks superseded job tokens cancelled before submit.
Worker waits in a while-predicate loop, takes pending out while holding the lock,
releases the lock, prepares listing, sends Prepared, then returns to waiting.
Never hold the mailbox mutex during I/O/sorting/channel.send.
The single slot plus one worker bounds work: one running job, one newest pending.
A displaced pending job's terminal event is sent by controller, not worker.

Controller owns:
  active: None | Preparing{id,token} | Delivering{id,prepared,offset}
Worker never emits wire events or changes controller state.
Controller transition table:
  list valid:
    if id equals current active id => fatal protocol error
    if active exists => cancel token if Preparing; emit cancelled once; drop it
    set Preparing(new id/token); submit newest Job
  Prepared(id,result):
    if active is not Preparing(id) => drop result; emit nothing
    if successful => emit listing; if total=0 emit done and clear active,
                     otherwise set Delivering(offset=0)
    if failure => emit error and clear active
  next(id):
    if Delivering(id) => emit next bounded batch; advance offset;
                        if end emit done and clear active
    if Preparing(id) => ignore (main API never sends this)
    if obsolete/unknown id => ignore
  cancel(id):
    if matching active => mark token cancelled if Preparing;
                          emit cancelled; clear active
    otherwise => ignore
  shutdown or InputClosed:
    mark current token cancelled, set mailbox.stopping, remove pending, notify;
    clear active and exit main loop/process normally
  FatalInput:
    same cleanup, stderr diagnostic, exit nonzero

Do not wait indefinitely to join worker or reader at shutdown. Returning from
main terminates the process; blocked OS enumeration is not hard-interruptible.
Main's 2-second kill fallback is the outer deadline. Connection closure replaces
terminal events during shutdown. A slow stdout consumer can backpressure main;
we promise bounded queues, not cancellation delivery to a consumer that refuses
to read. Normal UI keeps stdout draining.

Preparation checks token before opening, between entries, before filtering,
before sorting, after sorting. Cancellation is cooperative; sorting/OS calls
may complete before it is observed. No detached worker per cancelled request.

D7. Pull transport

Rust emits listing only after full preparation, then waits for next.
One next produces <=1 batch; final batch is followed by done. Empty emits
listing(total=0), done without next. All batches have contiguous offsets.
Main continuously parses stdout but does NOT automatically send next.

Main and renderer each enforce one next in flight. Clear that flag on batch or
terminal. After accepting a batch the renderer schedules the next pull using
setTimeout(..., 0) AFTER a React commit. This yields between batches without
requestAnimationFrame stalling enumeration in a minimized window.
Timers are cancelled on generation change/disposal.

If no single entry fits the byte cap, emit LIMIT_EXCEEDED, not an empty batch.
Compute exact encoded size as the serialized empty envelope (with correct id and
offset), plus each serialized entry's bytes, plus commas between entries.
Serialize each candidate entry once for sizing, then serialize the final bounded
batch once. Do not repeatedly serialize a growing array for every candidate.
Batch construction uses an index range into the prepared Vec; cloning at most
256 selected entries is allowed, cloning the whole listing is not. Keep only
one prepared result in the active controller.

D8. Main client API (class LiveBrowserClient)

Constructor receives the trusted absolute executablePath and an injectable spawn
function for tests (default node:child_process.spawn). It does not spawn yet.
Methods:
  start(): Promise<void>                 waits for ready, 5 second timeout
  list(path, options, onEvent): string   returns generated id synchronously
  next(id): void
  cancel(id): void
  close(): Promise<void>
onEvent receives wire listing/batch/done/cancelled/error, never ready.
A synthetic error may use SERVICE_UNAVAILABLE. list requires ready, validates
arguments and registers callback/state BEFORE writing the list command.
It locally retires the previous request immediately when a replacement starts.
Drop well-formed events for inactive/retired ids; validate structure before drop.
For active ids enforce listing once, listing before batch, contiguous offset,
batch count <= total, done only at total. Violations fail the connection.
Duplicate terminal for already retired id is ignored, not delivered twice.

Write queue is bounded to 32 commands and respects stdin.write false/drain.
Do not register an unbounded drain listener per command. Overflow fails the
connection visibly; never drop a command silently.
Keep stderr only as a last-8192-byte diagnostic buffer; do not log endlessly.

On failure: mark unavailable before callbacks, emit one synthetic error for the
active request, reject start if still waiting, clear timers/queue, terminate
child. Repeated close/error/exit callbacks must not repeat terminal delivery.
close is idempotent: send shutdown if possible, wait for exit, kill at 2 seconds.
Remove owned listeners and clear timers. Missing binary error includes the
poc:service:build command. Renderer cannot choose an executable path.

D11. Renderer state, races and controls

State:
  generation, requestId|null, phase idle|loading|receiving|complete|error,
  requestedPath, resolvedPath|null, parentPath|null, total|null,
  entries[], error|null, appliedOptions, selectedIndex|null
Defaults: filter="", kind=all, direction=asc.
Keep editable path/filter fields outside the reducer as draft form state.

Pure reducer actions:
  begin(generation,path,options): clear entries/error/id/parent/selection,
                                 phase loading, freeze appliedOptions
  attachId(generation,id): only current gen; accept id if null or same
  event(generation,payload): only current gen; bind null id from first event;
                            reject differing id for same generation
  select(index|null): only existing rows

event listing: require loading, set path,parent,total; phase receiving.
event batch: require receiving and contiguous offset, append in received order.
event done: require received length==total==payload.total; phase complete.
event cancelled: if current, clear rows, phase idle.
event error: clear rows, phase error.
Any current-generation ordering/id/count violation => phase error with
"Invalid listing response"; controller cancels request. No local sorting/repair.

A testable non-React BrowserController owns generation counter, current id,
subscription, pending start promises and cancellation. Accept API and onState
callback in constructor. Subscribe before first start. Methods:
  navigate(path,options), pullNext(), select(index), dispose()
Use the reducer for all state updates.
navigate increments generation BEFORE cancelling old request; dispatch begin;
invoke start. If start resolves for an obsolete generation, cancel its id.
If an event arrives before invoke resolution, bind its id via event.
A stale rejected promise must not overwrite current state. No new start in
response to a listing/error event.
dispose unsubscribes once and cancels current or late-resolving request IDs.

The React hook subscribes through controller callback, disposes on unmount, and
schedules one zero-delay pull after listing/batch commit when more rows remain.
For total=0 await done; never next. Await next rejection through current-gen
error handling. Prevent two pulls for the same received-count even when a
selection-only render runs. No indefinite setInterval polling.

Controls:
  path input + Go; Enter in path submits Go
  Choose Folder -> navigate only on non-null result
  Up -> parentPath with appliedOptions (disabled if parentPath null)
  Refresh -> last requested/resolved location with appliedOptions
  draft nameContains/kind/direction + Apply -> current location with new options
  draft edits alone do NOT start a request
  double-click selected directory or Enter in list -> its path, appliedOptions
  file/symlink/other activation -> no-op
New request clears selection and resets scroll top.
Keep Go usable while loading. Refresh/Apply disabled until a location exists.
Clear old rows immediately on begin; never show them under new location.
Status text: "Choose a folder", "Loading", "Loading X of Y", "No matching entries",
"Y entries", or error message. Show complete empty only after done.
